# 生成发布说明

## 使用的工具

`git_log` 拿提交清单，`git_diff` 拿改动规模。**不要**用 `read_file` 或 `search_code`，
发布说明关心的是「改了什么」而不是「代码怎么写的」，读源码只会浪费轮次。

## 步骤

1. 调用 `git_log`。用户明确给了版本区间就传 `range`（例如 `v1.0..HEAD`），
   只说了时间范围就传 `since`（例如 `2 weeks ago`）。两者都没说时用默认的最近 20 条。
2. 调用 `git_diff`，`from` 取区间起点、`to` 取终点，保持 `stat_only` 为 true。
   这一步是为了知道改动集中在哪些模块，不需要具体代码。
3. 把提交按下面的类别归并，然后输出。

## 输出格式

用中文输出，按这个结构：

```
## 版本变更说明（<起点> → <终点>）

### 新功能
- <一句话描述>（<短哈希>）

### 修复
- ...

### 重构与维护
- ...

### 改动概览
共 N 个提交，涉及 M 个文件，主要集中在 <目录/模块>。
```

## 注意事项

- 类别的判断依据是提交标题的语义，不要依赖 commit message 前缀（这个仓库没有强制 conventional commits）。
- 提交标题如果太简略，结合 `git_diff` 里该提交涉及的文件路径推断它实际做了什么，
  但要基于工具返回的事实，不要编造。
- 如果某个类别下没有内容，直接省略那个小节，不要写「无」。
